# StepWise — Classical-ML Approach

StepWise reads a student's handwritten arithmetic or linear-equation working, proves which
step is wrong, names the misconception, tracks mastery per skill, recommends practice, and
groups a class by misconception for the teacher.

Every learned component is a **classical machine-learning model** (scikit-learn or numpy/scipy),
trained on a laptop CPU in about 8 minutes, using real datasets where they exist (below). There are no neural networks, no GPU and no API keys.
TrOCR, Donut and the vision-API providers remain only as **optional deep-learning baselines** for
the OCR benchmark (`requirements-dl.txt`).

All numbers below come from `backend/ml_models/reports/*.json`. They are regenerated by
`python -m app.ml.train` (seed 0) and shown live on the **ML Lab** page.

## Real datasets used

| Dataset | Real? | Used for | Size used | Source / licence |
|---|---|---|---|---|
| **CROHME** train (Mouchère et al., ICDAR) | real handwriting | symbol recognizer training | 6,271 symbols from 1,337 expressions | HF mirror `Neeze/CROHME-full`, research use |
| **CROHME 2014 / 2016 / 2019 test** | real handwriting, unseen writers | **final symbol + expression evaluation** | 1,821 symbols, 127 whole expressions | official competition test sets |
| **HASYv2** (Thoma, 2017) | real handwriting | symbol recognizer training | 3,335 symbols, 144 writers | Zenodo 259444, ODbL |
| **ASSISTments 2009-2010** (Feng, Heffernan & Koedinger) | real student logs | knowledge-tracing benchmark + deployed BKT parameters | 446,844 answers, 4,151 students, 110 skills | pyBKT examples mirror, research use |
| Synthetic font glyphs | synthetic | robustness to printed/typed input | 12,210 glyphs, 24 fonts | generated |
| **ScratchMath** (songdj/ScratchMath) | **real student mistakes** + handwritten scratchwork photos | real-data error-type classifier (second opinion) | 1,720 wrong answers, expert-labelled (7 error types) | Hugging Face, CC BY-NC-SA 4.0 |
| Synthetic student solutions | synthetic | fine-grained mistake classifier | 3,150 solutions | generated |

Download everything with `make datasets` (about 1 GB, into the git-ignored `backend/data/external/`).
Nothing is redistributed with the repo.

**How CROHME symbols are labelled.** CROHME gives whole expressions with LaTeX labels, not
symbol boxes, so symbols are harvested by *count alignment*:

1. Keep only linear expressions (no fractions, scripts or roots).
2. Run the app's own segmenter on each one.
3. If it finds exactly as many symbols as there are LaTeX tokens, label the crops left to right.
4. Skip any expression where the counts don't match.

In a manual check of 80 random crops, 79 were labelled correctly.

## Pipeline

| # | Stage | Technique | Learned? |
|---|---|---|---|
| 1 | Clean-up | OpenCV: EXIF orientation, denoise, CLAHE, deskew, threshold | no |
| 2 | Segmentation | projection-profile lines → connected components → overlap merge (`=`) | no |
| 3 | **Symbol recognition (M1)** | HOG + zoning + aspect features → **SVM (RBF)** | yes |
| 4 | Formatting | canonical spacing; `x` between numbers → `*`; unary vs binary `-` | no |
| 5 | Step verification | SymPy (no `eval`): truth of each line, solution set of each equation | no |
| 6 | **Mistake diagnosis (M2)** | 33 named features → **Random Forest** (guardrails + rule fallback) | yes |
| 7 | Feedback | templates keyed by category | no |
| 8 | **Knowledge tracing (M3)** | **BKT** per skill (EM-fitted); PFA and EMA compared | yes |
| 9 | **Item difficulty + recommender (M3)** | **Rasch IRT** + ridge difficulty model; PFA-predicted P(correct) ≈ 0.7 | yes |
| 10 | **Class grouping (M4)** | standardized profiles → **K-Means** (k by silhouette), PCA map | yes (unsupervised) |
| 11 | **Active learning** | uncertainty-highlighted symbols → student corrections → retrain → versioned registry | loop |

## M1 — Symbol recognizer

- **Classes (17):** `0-9 + - = x ( ) /` (handwritten `×` is class `x`)
- **Features (374):** 28×28 aspect-preserving glyph → HOG (324) + 7×7 zoning (49) + log aspect ratio (1)
- **Training data:** CROHME train + HASYv2 (real) + synthetic font glyphs + student corrections
- **Choices** (training data and algorithm): made on validation data, using the mean macro-F1 over
  - 15% held-out CROHME-train expressions, and
  - 25% held-out fonts, because the app must also read printed worksheets.
- **Test:** the official CROHME 2014/2016/2019 test sets. They are written by people outside the
  training data and are never used for any choice.

**Does real data matter?** The same SVM was trained on three different datasets and tested on
real handwriting:

| Training data | Test symbol accuracy | Test macro-F1 | Whole expressions exactly right | Expression CER |
|---|---|---|---|---|
| Fonts only (previous model) | 0.553 | 0.573 | 0.22 | 0.452 |
| Real only (CROHME + HASYv2) | 0.927 | **0.913** | 0.575 | 0.120 |
| **Fonts + real** ✔ (selected on validation) | 0.926 | 0.899 | **0.575** | **0.110** |

The fonts-only model scored 0.975 on *held-out fonts* but only 0.573 on real handwriting, so
fonts are a poor proxy for real writers. "Fonts + real" was selected because it is as accurate
on real handwriting and still reads printed input (all 4 demo sheets correct). The real-only
model misreads some printed `4`s.

**Algorithms** (on fonts + real, tested on CROHME):

| Algorithm | Validation score | Test accuracy | Test macro-F1 |
|---|---|---|---|
| **SVM (RBF)** ✔ | 0.930 | 0.926 | 0.899 |
| Random Forest | 0.916 | 0.900 | 0.875 |
| Logistic Regression | 0.911 | 0.903 | 0.880 |
| kNN | 0.907 | 0.878 | 0.848 |

**Synthetic-only experiments** (kept for reference): held-out-font macro-F1 0.975, page CER 0.022.

## M2 — Mistake classifier

- **Classes (9):** correct, arithmetic slip, sign error, wrong operation, moving terms incorrectly,
  skipped step, final-answer mismatch, couldn't read clearly, not enough to check.
- **Features (33):** each one is named and explainable. Examples:
  - `sign_flip_term`, `op_swap_cross`, `off_by_place_value`
  - `cand_transpose_no_sign_change`, `cand_forgot_divide`
  - `nonequiv_pos`: the first line whose solution set differs from the previous line
  - `ocr_confidence`, `final_matches_expected`
- **Data:** 3,150 synthetic solutions, 350 per class, with one injected misconception each.
- **Split:** stratified 80/20. Selection by 5-fold CV on the 80%.

| Algorithm | CV macro-F1 | Test macro-F1 |
|---|---|---|
| **Random Forest** ✔ | **0.994** | **0.994** |
| Logistic Regression | 0.990 | 0.992 |
| Gradient Boosting | 0.988 | 0.991 |
| Decision Tree (depth 8) | 0.971 | 0.979 |
| Rule-based baseline (previous system) | – | 0.330 |

### M2b — Error type from REAL student mistakes (ScratchMath)

M2 needs step-by-step linear work with injected error types, and no public real dataset like that
exists. The closest real dataset is **ScratchMath**: 1,720 wrong answers from Chinese primary and
middle-school students. Each has the question, the correct answer, the student's answer, a
**photo of their handwritten scratchwork**, and an expert label from 7 error types (calculation,
misread question, concept, strategy, copying, reasoning, attention). A second classifier is
trained on it and shown as a **second opinion** on the Analysis page whenever an answer is wrong.

- **Features:** 42 language-independent features. The expert's written explanation is never used
  as an input, because it would leak the label.
  - *Answer patterns:* sign flip, decimal-point shift, one-digit copy slip, digit transposition,
    off-by-one, the student's value appears in the question or the reference solution (stopped
    early), missing ×/÷ by a number from the question, swapped blanks.
  - *Question statistics.*
  - *Scratchwork image statistics:* amount of ink, strokes and lines.
- **Split:** stratified 80/20 hold-out. Models are chosen by 5-fold CV on the 80%.

| Task | Majority baseline | Random baseline | Logistic Regression | Random Forest | Gradient Boosting |
|---|---|---|---|---|---|
| **Slip vs gap in understanding**: test accuracy | 0.552 | 0.480 | **0.683** ✔ (AUC 0.76) | 0.689 (AUC 0.77) | 0.704 (AUC 0.77) |
| **7 error types**: test accuracy / macro-F1 | 0.329 / 0.071 | 0.267 / 0.161 | 0.340 / 0.307 | **0.491 / 0.359** ✔ | 0.462 / 0.352 |

Adding Chinese question n-grams lifts 7-class macro-F1 to 0.407. That model can't read English
questions, so it is reported but not deployed. Telling **careless slips** from **understanding
gaps** is reliable enough to be useful (+13 points over the majority baseline). The 7-way label
is much harder, because the categories overlap.

At runtime, two guardrails run before the model:

- OCR confidence < 0.35 returns `transcription_uncertainty`.
- No parseable content returns `insufficient_information`.

If the model file is missing, the old rules are used, marked `source = deterministic`. Each
diagnosis lists the features that fired as human-readable evidence, plus the class probability
and the runner-up class.

## M3 — Knowledge tracing, IRT and recommender

- **Skills (8):** add/subtract, multiply/divide, negatives, brackets, one-step equations,
  two-step equations, moving terms, equations with negatives. Every submission and practice item
  maps to one skill (`app/ml/skills.py`).
- **Item bank:** 320 parametric items (40 per skill). Every answer is verified with SymPy in the tests.
### On real students: ASSISTments 2009

446,844 answers from 4,151 students across 110 skills, split learner-disjoint 80/20. The Rasch
regulariser was chosen on validation students taken from the training split.

| Next-answer prediction | AUC | RMSE | Log-loss |
|---|---|---|---|
| EMA (recency baseline) | 0.811 | 0.403 | 0.494 |
| BKT (EM, per skill) | 0.771 | 0.408 | 0.513 |
| PFA (logistic regression) | 0.787 | 0.404 | 0.490 |
| PFA + Rasch IRT | 0.781 | 0.413 | 0.525 |
| **PFA + IRT + recency features** ✔ | **0.815** | **0.396** | **0.476** |

This **differs from the simulation**: on real students the recency baseline beats plain BKT and
PFA. Skill-builder sets end after 3 correct answers in a row, so recent answers are very
predictive. Adding recency features (an EMA of the skill, last answer right/wrong) to the PFA
logistic regression gives the best model. Our BKT result (0.77) matches published BKT numbers
for this dataset.

**Deployed parameters:** BKT parameters for 7 of StepWise's 8 skills are now fitted on the
matching ASSISTments skills. For example, S3 ← "Addition and Subtraction Integers" +
"Multiplication and Division Integers". S8 has no match and keeps simulation-fitted parameters.

### On simulated learners (used where no real data exists)

- **Data:** 600 simulated learners (93,671 attempts). The simulator is a BKT+IRT generative
  model; see `app/ml/tracing/simulate.py`. **Split:** learner-disjoint 80/20.

| Next-answer prediction | AUC | RMSE | Log-loss |
|---|---|---|---|
| EMA baseline | 0.820 | 0.395 | 0.516 |
| **BKT (EM)** ✔ | **0.835** | **0.373** | **0.442** |
| PFA (logistic regression) | 0.832 | 0.381 | 0.454 |

- **BKT parameter recovery:** mean absolute error 0.021 against the simulator's true parameters.
- **Rasch item difficulty:** correlation with true difficulty 0.75. The ridge model on item
  features predicts difficulty for new items (CV R² 0.78). Number of steps, division and negatives
  make items hardest.
- **Recommender policy simulation:** 40 practice items per learner, 5 seeds.

| Policy | Skills mastered | Practice wasted on already-learned skills |
|---|---|---|
| Random | 0.638 ± 0.013 | 49% |
| Round-robin | 0.640 ± 0.010 | 47% |
| **Adaptive** (least-mastered skill, items at ≈70% predicted success) | **0.741 ± 0.008** | **28%** |

## M4 — Class grouping

- **Profile:** the rate of each error category plus BKT mastery per skill, standardized.
- **Method:** K-Means with k chosen by silhouette (2–6), compared against agglomerative (Ward).
  PCA gives the 2-D map. Clusters are named from their most elevated features, for example
  "Struggling with sign errors".
- **Simulated class with 4 planted archetypes:**
  - ARI vs the planted groups: **0.82**
  - Agreement between K-Means and agglomerative: 0.86 ARI
  - Silhouette: 0.25

## Active learning

1. Every recognized symbol is stored with its crop and confidence. The Analysis page colours
   boxes by confidence and lets the student click one to fix it.
2. Fixes are saved as labelled crops (`data/symbol_crops/labelled/<label>/`) and re-run the diagnosis.
3. **ML Lab → Retrain** builds a new version from synthetic glyphs plus all corrections.
   Corrections are always kept in training. The new version is compared on held-out fonts and
   registered **inactive**; activating it is an explicit click.

## Paper experiments (`python -m app.ml.paper_experiments`)

Written to `ml_models/reports/paper_experiments.json` and shown in ML Lab, on the symbol model's page.

**Classical ML vs deep learning.** Both systems read the same 127 real CROHME test expressions:

| System | Exact match | CER | ms / expression | Size |
|---|---|---|---|---|
| **StepWise HOG + SVM** | **0.567** [0.48, 0.65] | **0.115** | **48** | **8 MB** |
| TrOCR-base, zero-shot (334M params) | 0.284 [0.21, 0.36] | 0.369 | 1,325 | 1,336 MB |

The difference is significant (McNemar p = 1.3×10⁻⁷). TrOCR needs `pip install -r requirements-dl.txt`.

**Robustness to phone-photo conditions** (exact match on CROHME test expressions):

| Condition | Global Otsu | With illumination normalisation (deployed) |
|---|---|---|
| Clean | 0.567 | 0.567 |
| Uneven lighting | 0.031 | **0.567** |
| Combined (rotation + light gradient + blur + noise + JPEG) | 0.323 | **0.512** |

Blur, noise and JPEG compression barely matter. A 5° rotation costs about 8 points.

**Statistics:**
- *Deployed symbol model:* 92.4% accuracy (95% CI 91.2–93.6). It beats Random Forest (McNemar p = 5.5×10⁻⁶).
- *ScratchMath slip-vs-gap:* 68.3% (CI 63.1–73.0), significantly better than the majority baseline (p = 9.4×10⁻⁴).
- *ASSISTments:* PFA + IRT + recency reaches AUC 0.815 (CI 0.794–0.837). It is **not** significantly better than EMA (paired difference +0.005, CI −0.017 to +0.024).

**Ablations:**
- *Symbols:* HOG alone already gives 92.3%; zoning alone gives 75.2%.
- *Real mistakes:* answer-pattern features matter most. Removing them costs 4.7 points of slip accuracy.

**Reproducibility:** retraining every model from scratch with seed 0 reproduces all numbers exactly.

## Threats to validity (state these in the paper)

- **Symbols:** CROHME is tablet handwriting rendered to images, not phone photos of paper. Only
  linear expressions are harvested, and count alignment can mislabel a crop when two
  segmentation errors cancel out (about 1 in 80 in the manual check).
- **Mistake diagnosis:**
  - The fine-grained M2 (9 categories) is still synthetic-only, so its 0.99 is an upper bound.
  - The real-data model M2b (ScratchMath) uses a different, coarser label set and Chinese word
    problems, which is why only language-independent features are deployed.
  - A small English classroom set (100–200 photos) is still the best way to validate both.
- **Knowledge tracing:** ASSISTments skills are close to, but not the same as, StepWise's 8 skills.
  The item bank's difficulties and the recommender study still use simulated learners.
- **The simulator favours BKT and IRT,** because its generative model is BKT+IRT-like. The policy
  study only shows the benefit of choosing the right skill under that assumption.
- **Joined-up symbols break segmentation.** Cursive or touching symbols are under-segmented.

## Reproduce

```bash
cd backend
python scripts/download_datasets.py    # CROHME, HASYv2, ASSISTments (~1 GB)
python -m app.ml.train                 # all models (~8 min with real data); or --only real_symbols|real_tracing|...
python -m pytest tests -q              # 168 tests
python scripts/seed_demo_data.py && python scripts/seed_demo_class.py   # demo student + 24-student class
```
